# Database Layer (MongoDB Atlas)

Status: **IMPLEMENTED (foundation, Task 2).** Connection manager,
document validation, repositories, indexes, health-check and init
scripts, and unit tests exist. The Streamlit app does not use them yet.

## 1. Purpose

MongoDB Atlas stores **application data** produced when people use the
future Streamlit app:

- analysis history (what was analysed, predictions, model versions);
- user feedback on predictions;
- metadata about trained model versions.

**MongoDB does NOT store the ML training/validation/test datasets.**
Datasets stay as files under `data/` (git-ignored), processed by
versioned code, so experiments are reproducible independently of the
application database.

## 2. Configuration

| Setting | Source | Default |
|---|---|---|
| Connection string | env var `MONGODB_URI` | none — **required** |
| Database name | env var `MONGODB_DATABASE` | `meme_detection_db` (`config.yaml` → `database.default_database_name`) |
| Timeouts | `config.yaml` → `database.*_timeout_ms` | server selection 5 s, connect 10 s, socket 20 s |
| Collection names | `config.yaml` → `database.collections` | see below |

`config.yaml` stores only the *names* of the environment variables,
never their values.

### `.env` setup (local development)

1. In MongoDB Atlas: create a database user (Database Access) with the
   least privilege needed — `readWrite` on `meme_detection_db` — and
   allow your IP under Network Access.
2. Copy the connection string from Atlas → *Connect* → *Drivers*.
3. Open the git-ignored `.env` in the repository root (create it from
   `.env.example` if missing) and set:
   ```
   MONGODB_URI=<your connection string>
   MONGODB_DATABASE=meme_detection_db
   ```
   If the password contains special characters (`@ : / ? # [ ] %`) it
   must be URL-encoded in the URI.
4. Never paste the URI into chats, issues, screenshots, or code.

`python-dotenv` loads `.env` automatically (`override=False`, so real
environment variables — e.g. deployment secrets — take precedence).

## 3. Collections

All application IDs are **UUID4 strings** generated by the code. All
timestamps are **timezone-aware UTC** `datetime`s (millisecond
precision, matching MongoDB). MongoDB's internal `_id` is kept in the
database but not returned by the repositories.

### `analysis_history`

| Field | Type | Notes |
|---|---|---|
| `analysis_id` | UUID string | required, unique |
| `analysis_type` | `"text"` \| `"meme"` | required |
| `created_at` | UTC datetime | required |
| `processing_time_ms` | number ≥ 0 or null | optional |
| `model_versions` | object | optional; keys `text_model`, `image_model`, `multimodal_model` → model_id/version string |
| `input` | object | depends on type (below) |
| `predictions` | object | optional; slots below, each `{label, score}` |

Input fields:

| Type | Required | Optional |
|---|---|---|
| text | `original_text` | `normalized_text` |
| meme | — | `image_reference`, `image_metadata`, `ocr_text`, `normalized_text` |

Prediction slots: text → `text_model`, `final`; meme → `text_model`,
`image_model`, `multimodal_model`, `final`. Each prediction is
`{"label": <non-empty string>, "score": <finite number or null>}`.
`score` is not forced into [0, 1] because not every model outputs a
probability (e.g. an SVM decision value).

Example (structure only — labels are placeholders):

```json
{
  "analysis_id": "3f1c…-uuid",
  "analysis_type": "meme",
  "created_at": "2026-10-10T09:15:02.123Z",
  "processing_time_ms": 420.5,
  "model_versions": {"multimodal_model": "<model_id>"},
  "input": {
    "image_reference": null,
    "image_metadata": {"width": 800, "height": 600, "format": "JPEG"},
    "ocr_text": "…",
    "normalized_text": "…"
  },
  "predictions": {"multimodal_model": {"label": "<label>", "score": 0.71},
                  "final": {"label": "<label>", "score": 0.71}}
}
```

### `user_feedback`

| Field | Type | Notes |
|---|---|---|
| `feedback_id` | UUID string | required, unique |
| `analysis_id` | UUID string | required; must refer to an existing analysis |
| `rating` | `"correct"` \| `"incorrect"` | required |
| `comment` | string or null | optional |
| `created_at` | UTC datetime | required |

No users/accounts are stored (no authentication).

### `model_versions`

| Field | Type | Notes |
|---|---|---|
| `model_id` | UUID string | required, unique |
| `model_type` | `"text"` \| `"image"` \| `"multimodal"` | required |
| `model_name`, `version` | string | required |
| `architecture`, `training_dataset`, `preprocessing_version` | string or null | optional |
| `metrics_metadata` | object or null | optional; must hold **measured** metrics only, with their split (validation vs test) |
| `created_at` | UTC datetime | required |

**No model has been trained yet, so this collection is empty.** Records
are added only when a real trained model exists.

## 4. Validation rules

Implemented in `src/database/schemas.py` (plain Python, no extra
dependency). Every document is validated **before** it is written; an
invalid document raises `ValidationError` and nothing is inserted.

- required UUID IDs; valid `analysis_type` / `rating` / `model_type`;
- `created_at` must be timezone-aware UTC;
- `processing_time_ms` must be a finite number ≥ 0;
- unknown fields are rejected (catches typos);
- text vs meme analyses may only contain their own input fields and
  prediction slots;
- **no binary data anywhere** (`bytes` are rejected) and
  `image_reference` may not be an embedded `data:` URI — image binaries
  are never stored in documents;
- `image_metadata` is limited to `width`, `height`, `format`, `mode`,
  `size_bytes` (prevents storing EXIF data such as GPS location);
- **labels are not hard-coded** — they are not verified yet. Pass
  `allowed_labels` (e.g. from `config.yaml` `dataset.labels`, currently
  `null`) to the repository to restrict them.

## 5. Indexes

Created by `ensure_indexes()` (`src/database/indexes.py`), idempotent.

| Collection | Index | Purpose |
|---|---|---|
| analysis_history | `analysis_id` (unique) | lookup by ID, no duplicates |
| analysis_history | `created_at` desc | recent history |
| analysis_history | `analysis_type` + `created_at` desc | recent history filtered by type |
| user_feedback | `feedback_id` (unique) | lookup by ID |
| user_feedback | `analysis_id` + `created_at` desc | feedback for an analysis |
| user_feedback | `created_at` desc | recent feedback (dashboard) |
| model_versions | `model_id` (unique) | lookup by ID |
| model_versions | `model_type` + `created_at` desc | versions per model type |
| model_versions | `created_at` desc | all versions, newest first |

A compound index also serves queries on its first field alone, so no
separate single-field `analysis_type` / `analysis_id` / `model_type`
index is created.

## 6. Code layout

| File | Responsibility |
|---|---|
| `src/database/connection.py` | Settings from env/config, one reusable `MongoClient`, ping, safe errors, close |
| `src/database/schemas.py` | Building + validating documents, UUIDs, UTC timestamps |
| `src/database/repositories.py` | `AnalysisHistoryRepository`, `UserFeedbackRepository`, `ModelVersionRepository` |
| `src/database/indexes.py` | `ensure_indexes()` |
| `scripts/check_mongodb.py` | Connectivity health check |
| `scripts/init_database.py` | Create indexes |

Usage sketch for future code:

```python
from src.database.connection import get_connection
from src.database.repositories import AnalysisHistoryRepository

db = get_connection().db                 # one shared client per process
history = AnalysisHistoryRepository(db)
doc = history.create_analysis("text", {"original_text": "...", "normalized_text": "..."})
```

## 7. Connectivity testing and initialization

```bash
python scripts/check_mongodb.py
```
Prints `MongoDB connection successful.` (exit 0) or
`MongoDB connection failed: <safe reason>` (exit 1). It pings the
server and lists collections to prove access to the configured
database.

```bash
python scripts/init_database.py
```
Creates the indexes. It inserts **no** documents. MongoDB creates
collections lazily on first write; creating an index counts as a write,
so the three (empty) collections exist afterwards. Safe to re-run.

## 8. Error handling and security

- Missing/blank `MONGODB_URI` → `DatabaseConfigError` naming the
  variable only.
- Connection/auth/DNS failures → `DatabaseConnectionError` with a
  generic category message (unreachable / authentication failed / not
  authorized / invalid URI). PyMongo's raw error text is **not** shown
  because it can contain host names or URI fragments, and the original
  exception is not chained (`raise … from None`).
- `MongoSettings` hides the URI from `repr()`.
- Server selection timeout is 5 s, so failures are quick.
- Do not weaken Atlas security (e.g. allowing `0.0.0.0/0`) just to make
  a connection work; add your own IP instead.
- Unit tests never use real credentials: `MongoClient` is mocked, a
  fake in-memory database is used, and `.env` loading is disabled.

## 9. What is and is not stored

Stored: analysis metadata, submitted text / OCR text / normalized text,
basic image properties, predictions, model versions, processing time,
optional feedback.

Not stored: training datasets, image binaries, EXIF data, user accounts,
credentials, model weights.

**Open decisions (not made in Task 2):** whether uploaded images are
temporary only or stored by reference (object storage / GridFS);
retention period for history; whether submitted text should be stored
for every analysis or only with consent. `image_reference` is optional
so the "temporary only" option remains possible.
